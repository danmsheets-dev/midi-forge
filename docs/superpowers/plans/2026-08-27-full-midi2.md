# Full MIDI 2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> After user approval, also copy this plan to `docs/superpowers/plans/2026-08-27-full-midi2.md` (and the companion spec to `docs/superpowers/specs/2026-08-27-full-midi2-design.md`).

**Goal:** Make Midi-Forge a complete MIDI 2.0 diagnostic: every defined UMP type is named, constructed, and (where it has a MIDI 1 projection) downscaled; native UMP I/O on Windows MIDI Services and CoreMIDI; endpoint discovery, function blocks, and protocol negotiation.

**Architecture:** Keep `UmpMessage` as the only in-engine event. Finish the language in `midi-forge-core` (fixture-tested, no OS). Change downscale from a backend-wide habit to a **per-endpoint** policy (`ProtocolHint::Midi1Bytes` only). Add a Windows `WmsBackend` that bootstraps the MIDI App SDK COM initializer and talks `MidiSession` / `MidiEndpointConnection` in UMP words. WinMM remains the fallback for GS Wavetable and SDK-missing machines.

**Tech Stack:** Existing crates. Windows MIDI Services App SDK (`Microsoft.Windows.Devices.Midi2` winmd + COM bootstrapper CLSID `c3263827-c3b0-bdbd-2500-ce63a3f3f2c3`). `windows` / `windows-bindgen` for the projection. CoreMIDI already uses `Protocol::Midi20`. No crates.io `midi2` crate (would duplicate `UmpMessage`).

**Assumed scope (recommended):** complete UMP + native I/O. Explicitly **out of this plan:** full MIDI-CI Property Exchange JSON sessions, Network MIDI 2.0 auth/session state machine, MIDI Clip File / SMF2. Those stay as the current inquiry / UDP-subset / SMF0-downscale.

## Key decisions

1. **Per-endpoint downscale.** `MidiBackend::send` must not downscale blindly. Helper: `fn packets_for_wire(ep: &Endpoint, pkt: &UmpMessage) -> Vec<UmpMessage>` — identity if `protocol == Ump`, else `downscale_to_midi1`. WinMM endpoints stay `Midi1Bytes`. Loopbacks, WMS, and CoreMIDI MIDI 2 ports stay `Ump`.

2. **Prefer WMS, fall back to WinMM.** `default_backend()` on Windows: try `WmsBackend::try_new()`; on SDK/service failure return `WinMmBackend` and surface the reason in the banner. Do not remove WinMM — GS Wavetable and some `.drv` mappers are WinMM-only.

3. **SDK bootstrap is COM, not a crates.io crate.** CoCreate `MidiDesktopAppSdkInitializer` (`CLSID c3263827-c3b0-bdbd-2500-ce63a3f3f2c3`, `IID 8087b303-d551-bce2-1ead-a2500d50c580`), call `InitializeSdkRuntime` + `EnsureServiceAvailable`, then activate `MidiSession`. Generate Rust bindings from the installed/NuGet `Microsoft.Windows.Devices.Midi2.winmd` via `windows-bindgen`. If the winmd is absent at build time, `WmsBackend` is compiled out or returns `Unsupported` — never fake a session.

4. **Do not adopt the `midi2` crate.** Extend `midi-forge-core` modules. Canonical packet stays `[u32; 4] + len`.

5. **Stream / Flex / SysEx8 live in core, not the GUI.** Trackers assemble multi-packet messages; the monitor shows named summaries; the GUI only snapshots.

6. **Protocol negotiation is automatic on UMP open.** Opening a WMS/CoreMIDI UMP connection sends Endpoint Discovery + Function Block Discovery + Stream Configuration Request (MIDI 2 protocol). Replies update an `EndpointStream` snapshot (name, identity, function blocks, JR caps, current protocol).

7. **Live/MPE/hang stay 7-bit projections internally unless cheap.** Monitor and inject show native MIDI 2. Live view gets a 32-bit + per-note map *without* throwing away type `0x4` (stop calling `downscale_to_midi1` as the only path). SMF0 record still downscales — SMF0 is MIDI 1.

8. **Groups are first-class.** Inject and CLI gain `--group` / a Group spinner (0–15). Decode already has `group`.

## Phase A — Finish MIDI 2 channel voice (type 0x4)

**Files:** `midi2.rs`, `decode.rs`, `filter.rs`

### Task A1 — Note attributes

MIDI 2 Note On/Off: `data2` = attribute type; word1 low 16 = attribute data. Types: `0` none, `1` manufacturer, `2` profile, `3` pitch 7.9.

- [ ] **Step 1: Failing tests** in `midi2.rs`:

```rust
#[test]
fn note_on_attribute_roundtrip() {
    let m = midi2_note_on_attr(0, 1, 60, 0x8000, 3, 0x1234);
    assert_eq!(m.data2(), 3);
    assert_eq!(m.words()[1] & 0xFFFF, 0x1234);
    match crate::decode(&m) {
        crate::Decoded::Midi2NoteOn { attribute_type, attribute_data, velocity, .. } => {
            assert_eq!(attribute_type, 3);
            assert_eq!(attribute_data, 0x1234);
            assert_eq!(velocity, 0x8000);
        }
        other => panic!("{other:?}"),
    }
}
```

- [ ] **Step 2: Run** `cargo test -p midi-forge-core note_on_attribute_roundtrip -- --nocapture`  
  Expected: FAIL (no `midi2_note_on_attr` / no fields)

- [ ] **Step 3: Implement**

```rust
pub fn midi2_note_on_attr(
    group: u8, channel: u8, note: u8, velocity: u16, attr_type: u8, attr_data: u16,
) -> UmpMessage {
    UmpMessage::midi2_channel_voice(
        group,
        0x90 | (channel & 0x0F),
        note,
        attr_type,
        (u32::from(velocity) << 16) | u32::from(attr_data),
    )
}
```

Extend `Decoded::Midi2NoteOn` / `Midi2NoteOff` with `attribute_type: u8`, `attribute_data: u16`. Summary: omit when type is 0, else `attr {type} {data:#06X}`. Existing `midi2_note_on` stays as type 0.

- [ ] **Step 4: Tests pass; downscale still ignores attributes** (MIDI 1 has none).

- [ ] **Step 5: Commit** `feat(midi2): note on/off attribute type and data`

### Task A2 — Relative registered / assignable controllers

Status nibbles `0x40` (relative RC) and `0x50` (relative AC). Value is two’s-complement i32 in word1. No MIDI 1 short form — keep dropping on downscale.

- [ ] Tests: construct `midi2_registered_controller_relative`, decode `kind_key == "m2_rc_rel"`, downscale empty.
- [ ] `Decoded::Midi2RegisteredControllerRelative { bank, index, delta: i32 }` and AC twin.
- [ ] Filter already maps `0x40|0x50` to `ControlChange` — keep that.
- [ ] Commit `feat(midi2): relative registered/assignable controllers`

### Task A3 — Upscale helper (MIDI 1 → MIDI 2 CV)

Needed so a MIDI 1 source can be rewritten onto a UMP dest without staying type `0x2`.

```rust
pub fn upscale_to_midi2(packet: &UmpMessage) -> UmpMessage
```

- MIDI 1 note/CC/pressure/bend/PC → type `0x4` via existing `velocity7_to_16` / `value7_to_32`.
- Type `0x4` and non-CV pass through.
- Tests: 127 vel → 65535; CC 64 → `64 << 25`.
- Thru map action later: `VoiceKind` already covers this; add `MapAction::ForceMidi2` in Phase F if a test wants it. Skip map UI until Phase G.
- Commit `feat(midi2): upscale MIDI 1 channel voice to type 0x4`

## Phase D — Flex Data (type 0xD)

| Status | Name | Fields |
|--------|------|--------|
| Set Tempo | 10 µs / quarter | u32 |
| Set Time Signature | nn / dd / cc / bb | |
| Set Metronome | accents | |
| Set Key Signature | sf / mi | |
| Text / Lyric / Rehearsal | UTF-8 chunks | assemble |

- [ ] Tests: tempo 500_000 µs/qn decodes as 120 BPM; lyric start+end concatenates.
- [ ] `Decoded::FlexTempo { microseconds_per_quarter }`, `FlexTimeSig`, `FlexMetronome`, `FlexKeySig`, `FlexText { kind, text }`.
- [ ] Clock panel: if Flex tempo seen, show “Flex tempo 120.00” next to host BPM (do not overwrite MIDI 1 clock BPM).

## Phase E — UMP Stream, function blocks, protocol negotiation (type 0xF)

**Files:** new `ump_stream.rs`, `decode.rs`, new app `stream.rs`

Stream messages have **no Group** in the MIDI 1 sense (form nibble in the group field). Status (high 10 bits of word0, spec layout):

| Status | Message |
|--------|---------|
| 0x00 | Endpoint Discovery (filter bitmap) |
| 0x01 | Endpoint Info Notification (UMP ver, n function blocks, MIDI 1/2 caps, JR tx/rx) |
| 0x02 | Device Identity Notification |
| 0x03 | Endpoint Name Notification (chunked UTF-8) |
| 0x04 | Product Instance Id Notification |
| 0x05 | Stream Configuration Request (protocol + JR) |
| 0x06 | Stream Configuration Notification |
| 0x10 | Function Block Discovery |
| 0x11 | Function Block Info (fb#, dir, MIDI 1/2, first group, n groups, ci) |
| 0x12 | Function Block Name |

- [ ] Tests with golden 4-word fixtures for discovery request, info notify (MIDI 2 + JR rx), one function block info, chunked name “Forge”.
- [ ] `StreamTracker`: feed packets → `EndpointStream { name, product_id, identity, midi1, midi2, jr_tx, jr_rx, protocol, blocks: Vec<FunctionBlock> }`.
- [ ] Constructors for the three inquiries (discovery filter `0x1F`, FB discovery `0x03`, stream config request protocol=2).
- [ ] GUI: **Stream** subpanel on the endpoint list (selected input): name, protocol, JR caps, function-block table (id, groups, MIDI 1/2, name).
- [ ] On UMP input/output **open**, engine sends the three inquiries (do not send on WinMM).
- [ ] Commit `feat(ump): stream discovery, function blocks, protocol negotiation`

## Phase F — Per-endpoint I/O policy (fixes CoreMIDI send)

**Files:** `backend.rs`, `coremidi.rs`, `winmm.rs`, `loopback.rs`, `null.rs`

```rust
pub fn packets_for_wire(protocol: ProtocolHint, packet: &UmpMessage) -> Vec<UmpMessage> {
    match protocol {
        ProtocolHint::Ump => vec![*packet],
        ProtocolHint::Midi1Bytes => downscale_to_midi1(packet),
    }
}
```

- [ ] Test in `backend.rs` or `loopback.rs`: MIDI 2 note on a UMP dest has type `0x4` after send; same packet to `Midi1Bytes` is type `0x2`.
- [ ] **CoreMIDI `send`:** look up endpoint protocol; call `packets_for_wire`; `event_buffer` already picks `Protocol::Midi20` when `message_type() >= 0x4`. Tag real CoreMIDI sources with MIDI 1 vs MIDI 2 if the crate exposes protocol; default virtual dests stay UMP.
- [ ] **WinMM `send`:** keep `Midi1Bytes` (already).
- [ ] **Null / loopback:** UMP, no downscale.
- [ ] Banner: `native UMP` iff `caps.native_ump` **and** the selected dest is `ProtocolHint::Ump`.
- [ ] Commit `fix(io): downscale only MIDI 1 endpoints`

## Phase G — Native Windows `MidiSession` backend

This is the product gap. All previous phases work on loopback/CoreMIDI without it.

**Files:** new `wms_session.rs`, `backend.rs` `default_backend()`, `wms.rs`, `Cargo.toml`

### G1 — Bootstrap

- [ ] `WmsInit::try_new() -> Result<Self, IoError>`:
  1. `CoInitializeEx(MTA)` on the engine thread (already owns the backend).
  2. `CoCreateInstance` initializer CLSID / IID above.
  3. `InitializeSdkRuntime` + `EnsureServiceAvailable`.
  4. Failure → `IoError::Backend("Install SDK: winget install Microsoft.WindowsMIDIServicesSDK")`.

- [ ] Unit test: skip if COM create fails; `#[cfg(windows)]` ignored integration `wms_init_or_skip`.

### G2 — Bindings

- [ ] Add Windows-only deps: `windows` (COM + Foundation), `windows-bindgen` **build-dep** if generating from winmd.
- [ ] Build script: if `MIDI2_WINMD` env or `vendor/Microsoft.Windows.Devices.Midi2.winmd` exists, generate; else compile a stub `WmsBackend::try_new() -> Err`.
- [ ] Document in README: copy winmd from the NuGet (`Microsoft.Windows.Devices.Midi2`) into `vendor/` **or** install the SDK runtime.

Do **not** check a multi-MB native DLL into git. Runtime is the user’s installed App SDK.

### G3 — `WmsBackend: MidiBackend`

Enumeration: `MidiEndpointDeviceInformation` / watcher → `Endpoint { id: "wms:{deviceId}", protocol: Ump, direction: Bidirectional }` (WMS endpoints are bidirectional UMP; split in/out in the UI as two rows if the information object says so).

Open: `MidiSession::Create("Midi-Forge")` once; `CreateEndpointConnection(id)` + `Open()`; subscribe `MessageReceived` → push `UmpMessage::try_from_words` into the same 4096 sync_channel pattern as WinMM.

Send: `connection.SendMessageStruct` / COM extension words; **no downscale**. SysEx: send SysEx7/8 UMPs, not WinMM long headers.

Caps: `native_ump: true`, `scheduled_send: true` (MidiClock timestamps), `daw_visible_virtual: true`, `multi_client: true`.

Loopback: prefer SDK loopback creation APIs; keep `midi.exe` as fallback.

- [ ] Tests: with Null-style fake if SDK missing; ignored live test `#[ignore] fn wms_roundtrip_loopback`.
- [ ] `default_backend()`: `WmsBackend::try_new().unwrap_or_else(|_| WinMmBackend::new())`.
- [ ] Commit `feat(io): Windows MIDI Services MidiSession backend`

### G4 — Scheduled send (optional same PR if small)

`BackendCaps.scheduled_send`: `send` uses immediate; new `send_at(id, packet, timestamp_100ns)` on the trait with default `send`. Clock master can later attach JR or WMS timestamps. **If this blows the PR, ship G3 without it** and leave `scheduled_send: false` until Phase H.
